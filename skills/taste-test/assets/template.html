Background

Deep background (skip if you know the save path)

Every editor save goes through DocumentService.save, which writes the content to storage and emits a saved event. Three listeners react to that event: search indexing, the activity feed and the autosave timer.

Autosave fires every five seconds, also when nothing changed. That produces about 700 identical writes per document and hour.

Intuition

Before

autosave"Hello" save()write storagev42

After

autosave"Hello" hash checksame as v42 cached resultv42

The save path now compares a hash of the content with the last saved hash and returns early when they match.

Content hash

A short fingerprint of the content. Equal content gives an equal hash, so the comparison costs one string compare instead of a storage read.

Code

The shape first: one new step in the save path, one new step after the write.

 on(save)
-  write content
+  if hash(content) == lastHash
+    return cached result
+  write new content
+  lastHash = hash(content)

The hash lives on the service instance (src/documents/service.ts:41), so every document tab keeps its own value.
